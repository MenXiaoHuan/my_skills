# Quality Gates

本文件是覆盖计算、重复裁决、最小充分集和质量门禁的唯一权威。

## 覆盖计算

覆盖率由最终选中 case 的 `coverage_atoms` 反向计算。不得手填覆盖维度、用例数量或覆盖率。

必须计算：

- 必选 atom 覆盖
- 来源与业务目标覆盖
- 高风险目标的正向和关键失败路径覆盖
- 受控维度覆盖
- API contract 覆盖
- 数据不变量覆盖
- 状态迁移覆盖

## 重复识别

标题归一化移除优先级前缀、空格和末尾标点。验证意图指纹使用：

```text
模块 + 业务对象 + 前态 + 触发动作 + 条件 + 断言目标 + 后态
```

指纹一致的候选进入重复簇。coverage atoms 相同的候选也进入裁决，但不同 `path_type`、角色、权限、前后态、请求契约、恢复行为或业务结果必须保留独立 case。

只有输入数据不同且意图、状态和预期相同的候选优先合并为参数化 case。若 B 的 atoms 完全包含于 A，且 A 不混合无关意图、前置不更昂贵、步骤成本没有明显增加，可删除 B。

## 最小充分集

按候选原顺序稳定打破同分：

```text
score = 新增 atom 风险权重 + 高风险路径奖励 - execution_cost - 与已选 atom 重叠数
```

持续选择，直到所有必选 atoms 与高风险必要路径覆盖，或剩余缺口都有明确阻断原因。P0/P1 独立风险、权限泄漏、数据损坏和不可恢复状态不得因集合压缩而删除。

## 阻断门禁

- case tree schema 完整率为 100%
- group、case、preconditions、action 和 expected 不为空
- priority 只允许 `P0/P1/P2/P3`
- 标题优先级前缀与字段一致
- `preconditions`、`action`、`expected` 无末尾中文句号
- 必选 atoms 全部覆盖
- 高风险目标正向和关键失败路径全部覆盖
- API case 有接口来源
- 数据一致性 case 有数据不变量引用
- 重复簇完成保留、合并或删除裁决
- XMind 可生成、可解压、XML 可解析且层级正确

任一阻断门禁失败时不得交付 final；信息不足时输出 `draft` 或报告精确失败。

## 警告门禁

- 假设数量异常
- 分类过度集中
- P0/P1 占比异常
- 平均步骤过少或过多
- `其他` case 占比过高
- 单个 case 覆盖过多无关 atoms

警告需要审阅，但不自动阻断。质量报告使用 `templates/quality-report.template.json`，默认保持内部可见。
