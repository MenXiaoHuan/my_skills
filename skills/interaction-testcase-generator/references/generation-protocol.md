# Generation Protocol

本文件是信息缺口、候选模式、覆盖生成和候选裁决的唯一权威。

## Ask、Assume 与 Draft

缺口会改变范围、核心流程、角色权限、预期结果、接口契约、数据口径或发布风险时追问。仅缺少次要限值、示例或默认值，且不影响核心含义时，可以继续并把假设写入内部 IR。

以下内容不得静默假设：

- 核心流程和审批或状态迁移
- 角色权限
- API 方法、参数、响应和副作用
- 指标定义和数据一致性时机
- 会改变范围的系统依赖

核心事实缺失、材料冲突或关键结论主要依赖假设时输出 `draft`。记录冲突来源，不合并互相矛盾的结论。

## 五阶段协议

### 证据提取

为需求、原型、API、技术设计、数据定义和明确假设分配稳定 source ID。提取业务目标、角色、模块、工作流、状态、规则、接口、数据实体、不变量、依赖和风险。关键事实的 `source_refs` 不得只指向 `assumption`。

### IR 与 Coverage Atoms

按 `test-model.md` 建立 IR。把每个可独立验证的事实转为 coverage atom，包含 `kind`、`target_ref`、`required`、`risk_weight` 和来源。覆盖数据必须由候选映射计算，禁止填写 `covered_dimensions`、`final_case_counts` 等可推导结果。

### 候选模式

简单、低风险、单模块且无接口或跨系统链路时，生成一个候选集，再由独立视角执行 gap scan。

满足任一条件时生成两个内部候选集：

- 高风险目标
- 多模块
- 包含 API 证据
- 跨系统、异步、审批或补偿链路

`coverage-first` 关注目标、失败路径、权限、状态、依赖和回归面；`quality-first` 关注单一验证意图、可构造前置、可观察断言、来源和重复控制。

## Gap Scan

候选生成后扫描：

- 正向与关键失败路径
- 权限和越权
- 状态合法与非法迁移
- 超时、失败、重试、回滚、补偿和降级
- 空数据、部分数据和不一致数据
- 阈值、时间窗、枚举、重复操作和并发
- API 契约和副作用
- UI、API、详情、列表、导出和下游的一致性

只有材料支持的缺口才扩展为 case；其余记录为信息缺口或假设。

## 裁决

先冻结来源支持的模块或工作流集合，再按 `quality-gates.md`：

1. 删除 schema 不完整和无来源候选。
2. 识别标题归一化重复与验证意图指纹重复。
3. 对 coverage atoms 相同但路径、角色、状态、契约或预期不同的候选保留独立 case。
4. 对可参数化的数据差异执行合并。
5. 在不丢失 P0/P1 独立风险、权限泄漏、数据损坏和不可恢复状态的前提下选择最小充分集。
6. 执行第二次 gap scan 和全部阻断门禁。

最终只输出一个裁决后的结果。原始候选与裁决草稿保持内部可见。
